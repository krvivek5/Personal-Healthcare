## 1. M2 Product Goal and User-Visible Capability

### Product Goal
The goal of Milestone 2 is to prove the integration of **one production LLM provider** behind a provider-neutral, privacy-preserving **LLM Gateway**, replacing the deterministic `MockLLMProvider` in live environments while strictly preserving all Milestone 1 (M1) architectural invariants:
1. **The Backend Owns Evidence Truth; The LLM Owns Language Synthesis**: The backend deterministically governs record existence, attribute presence/null state, temporal state, and overall evidence sufficiency. The LLM is restricted strictly to plain-language comprehension and synthesis within backend-defined evidence boundaries.
2. **Deterministic Safety Primacy**: The system operates strictly within non-diagnostic, non-triage, and non-prescriptive limits. Deterministic pattern-based safety guardrails take absolute precedence over model inference.
3. **Provider-Neutral Portability**: The gateway treats the LLM as replaceable infrastructure. While M2 implements exactly one production provider (OpenAI), the abstraction guarantees zero application coupling to vendor-specific SDKs or non-portable idioms.
4. **Patient-Data Minimization Boundary**: External model payloads transmit only the minimal sanitized health data necessary to address the query, with zero exposure of database primary keys, tenant IDs, or unrelated clinical context.

### User-Visible Capability
In Milestone 1, authenticated users submitting inquiries received canned, deterministic template text generated by `MockLLMProvider` (e.g., *"Records confirm Asthma. Attributes name are present."*).

In Milestone 2, the user experiences:
* **Natural Conversational Synthesis**: Plain-language, fluent, and empathetic explanations summarizing their personal health records in response to natural language inquiries.
* **Grounded Answers with Verified Citations**: Complex multi-record histories (e.g., comparing active medications with stopped medications, or contextualizing recorded allergies) are synthesized clearly, with bracketed citations (e.g., `[1]`, `[2]`) linked directly to verified structured records in the provenance drawer.
* **Honest, Plain-Language Gap Communication**: When queried information is missing or partially unrecorded, the response naturally and unambiguously explains that the records do not contain this information, strictly adhering to backend directives without speculative guessing or clinical negative claims.
* **Instant Safety Advisories**: Inquiries describing acute symptoms immediately present the prominent M1 safety advisory directing the user to professional/emergency care.

## 2. Exact Scope and Explicit Non-Goals

### Exact In-Scope Deliverables (M2)
* **LLM Gateway Core**: A provider-neutral abstraction implementing the existing `LLMProvider` protocol in `backend/app/core/llm.py`, featuring a factory dispatcher and `MockLLMProvider` fallback for offline CI/CD.
* **Single Production Provider Adapter (OpenAI `gpt-4o-mini`)**: A dedicated adapter utilizing asynchronous HTTP transport (`httpx.AsyncClient`) and native JSON Schema output constraints to communicate with OpenAI's chat completions API.
* **Future Extension Interfaces**: Architectural blueprint defining pluggable adapter contracts for Anthropic and Google Gemini (retained as future extension targets, not implemented in M2).
* **Patient-Data Minimization & Reference Tokenization**: Sanitization pipeline stripping internal database identifiers and mapping clinical records to short reference tokens (`[REC-1]`, `[REC-2]`) in prompts.
* **Deterministic Server-Side Citation Reconciliation**: Mapping emitted reference tokens back to patient record UUIDs and verifying patient ownership against the authoritative record set.
* **Defense-in-Depth Safety Pre-Flight**: Interceptor in the gateway ensuring that safety-triggered queries produce **no external LLM network call** and immediately return the unaltered M1 `SAFETY_ADVISORY`.
* **Prompt Construction Pipeline**: Assembling system boundaries, sanitized tokenized context, authoritative backend evidence directives, and user query into a grounded prompt.
* **Structured Output Shape Validation**: Enforcing syntactic Pydantic validation on model output while delegating factual and citation validity entirely to server-side checks.
* **Failure Mode Interceptors**: Handling network timeouts, HTTP 429 rate limits, HTTP 5xx provider degradation, malformed JSON, and provider safety refusals.
* **Privacy-Preserving Observability**: Telemetry capturing token usage, latency, error types, and model identifiers while strictly redacting Protected Health Information (PHI).
* **Automated Comparative Evaluation Suite**: Test harness evaluating live LLM outputs against deterministic M1 benchmarks across all 7 evaluation categories.

### Explicit Non-Goals (M2)
To prevent architectural scope creep, M2 explicitly excludes:
* **NO Multi-Provider Implementation in M2**: Only ONE real provider (OpenAI) is implemented in M2. Anthropic and Gemini are documented as future targets.
* **NO Medical-Document Content Extraction (OCR / PDF parsing)**: Milestone 3.
* **NO Embeddings, Vector Databases, or pgvector RAG**: Milestone 4.
* **NO Multi-Turn Conversational Memory or Chat Session State**: Milestone 5.
* **NO Streaming Responses (SSE / Chunked Transfer)**: M2 remains synchronous.
* **NO Autonomous Agents or Tool Calling**: The LLM does not execute functions or tools.
* **NO Proactive Monitoring or Trend Detection**: Phase 3.
* **NO Wearable or Biometric IoT Sensor Streaming**: Out of scope.
* **NO Clinical Decision Support (CDS)**: No diagnostic algorithms, drug interaction engines, or clinical risk scoring.
* **NO Weakening of M1 Safety or Evidence Invariants**: Deterministic guardrails and evidence evaluation remain unchanged and authoritative.

The gateway preserves the existing `LLMProvider` protocol interface while introducing an extensible dispatch pattern:

```
                  ┌──────────────────────────────────────────────┐
                  │          FastAPI Request Handler            │
                  │   (backend/app/api/health_inquiry.py)        │
                  └──────────────────────┬───────────────────────┘
                                         │
                                         ▼
                  ┌──────────────────────────────────────────────┐
                  │                 LLM Gateway                  │
                  │        (backend/app/core/llm_gateway.py)     │
                  │   - Defense-in-depth safety pre-flight       │
                  │   - Provider factory & timeout control       │
                  │   - Fallback dispatcher                      │
                  └──────────────┬───────────────────────────────┘
                                 │
         ┌───────────────────────┴───────────────────────────────┐
         │ (Configured Provider)                                 │ (Default / CI fallback)
         ▼                                                       ▼
┌─────────────────────────────────┐                    ┌─────────────────────────┐
│         OpenAI Adapter          │                    │     MockLLMProvider     │
│       (Implemented in M2)       │                    │    (Locked M1 Logic)    │
│  - httpx async transport        │                    │  - Deterministic tests  │
│  - JSON Schema output constraint│                    │  - Offline execution    │
│  - Token reconciliation         │                    └─────────────────────────┘
└─────────────────────────────────┘
                 ┆
   (Future Extension Targets - Post-M2)
   ┌ - - - - - - - - - - - - - - - - ┐
   ┆  Anthropic Adapter (Future)     ┆
   ┆  Gemini Adapter (Future)        ┆
   └ - - - - - - - - - - - - - - - - ┘
```

### Architectural Responsibilities

1. **`LLMGateway`**:
   - Implements `LLMProvider.synthesize_response(...)`.
   - **Defense-in-Depth Safety Pre-Flight**: Inspects `safety_state.triggered`. If `True`, intercepts execution before touching the network, returning `SynthesisResult(answer_text=safety_state.advisory_message, cited_record_ids=[])`.
   - Inspects `settings.LLM_PROVIDER`. If set to `openai` and `LLM_API_KEY` is present, delegates to `OpenAIAdapter`. Otherwise, falls back gracefully to `MockLLMProvider`.
   - Wraps external calls with configurable timeout and retry boundaries.

2. **`OpenAIAdapter` (Single Real Provider in M2)**:
   - Uses `httpx.AsyncClient` targeting the OpenAI `/v1/chat/completions` REST endpoint.
   - Leverages OpenAI's native Structured Outputs (`response_format={"type": "json_schema", ...}`) to constrain the syntactic structure of the response.
   - Operates with temperature $T=0.0$ to prioritize grounded consistency over creative variance.

3. **`MockLLMProvider` (Preserved & Authoritative Fallback)**:
   - Retains the exact, locked M1 deterministic logic.
   - Remains the default provider in test environments and CI/CD pipelines where external network access is unavailable or disabled.

## 4. Provider Abstraction and Portability Strategy

> [!IMPORTANT]  
> The system treats the LLM provider as replaceable infrastructure. Implementing a single provider in M2 must not introduce architectural coupling that complicates future migrations.

### Comparative Provider Analysis & Future Extension Targets

While M2 implements **only OpenAI**, the gateway design explicitly accounts for the architectural characteristics of the three leading platforms:

| Provider | M2 Status | Architectural Characteristics | Role in Portability Strategy |
| :--- | :--- | :--- | :--- |
| **OpenAI**<br>(`gpt-4o-mini`) | **Implemented in M2** | • **Native Structured Outputs (`json_schema`)**: Enforces syntactic adherence to Pydantic output grammar at the tokenizer level.<br>• Mature async REST API and reliable latency.<br>• Straightforward prompt adherence. | Primary proof provider for M2 live synthesis. |
| **Anthropic**<br>(`claude-3-5-haiku`) | *Future Extension Target (Post-M2)* | • Exceptional steerability on negative boundary constraints ("do not extrapolate", "do not diagnose").<br>• Structured outputs require Tool Calling (`tool_choice`) rather than grammar constraints.<br>• High factual precision. | First secondary adapter to be added post-M2 to prove multi-vendor portability. |

2. **Agnostic Internal Representation**: The application layer receives only the generic `SynthesisResult` schema. All vendor-specific request/response envelopes are strictly quarantined within the adapter file.

## 5. Patient-Data Minimization Boundary

Sending health data to an external provider requires a strict, defensive data-minimization boundary:

### 1. Elimination of System Identifiers
The external LLM payload NEVER receives:
* Database primary keys: `patient.id`, `user_id`, or UUID primary keys of records.
* Surrogate keys & metadata: `source_id`, `storage_key`, `upload_id`.
* Audit timestamps: `created_at`, `updated_at`.
* Account metadata: email, authentication tokens, tenant references.

### 2. Reference Tokenization (`[REC-N]`)
Real LLMs are notoriously prone to transposing, truncating, or hallucinating 36-character UUID strings.
* **Prompt Representation**: Records are formatted with localized, ordinal reference tokens:
  ```
  [REC-1] Condition: Asthma | Status: active | Diagnosed: 2021-03-15
  [REC-2] Medication: Lisinopril 10mg | Status: active | Frequency: once daily
  [REC-3] Medication: Amoxicillin 500mg | Status: stopped | Stopped: 2023-06-10
  ```
* **Output Constraint**: The model cites only the reference tokens: e.g., `cited_references: ["REC-1", "REC-2"]`.
* **Deterministic Server Reconciliation**: The adapter maintains an in-memory map `{ "REC-1": uuid.UUID("..."), "REC-2": uuid.UUID("...") }` constructed strictly from the retrieved patient records. Emitted tokens are deterministically translated back to database UUIDs. Tokens not present in the map are discarded.

### 3. Query-Scoped Minimization
If an inquiry targets a specific domain (e.g., "What medications am I taking?"):
* Only the general profile (biological sex, age) and the queried domain (`medications`) are serialized into the prompt.
* Unrelated sensitive records (e.g., mental health symptoms or unrelated allergies) are omitted from the prompt payload, reducing data exposure and token usage.

## 6. Prompt Construction and Structured Output Validation

### Core Prompt Principle
> **"The prompt instructs language generation; the server enforces factual truth."**

### Prompt Layout
The dynamic prompt is partitioned into four distinct blocks:

1. **System Prompt (Inviolable Rules & Prohibitions)**:
   - Role definition: Plain-language health record synthesis assistant.
   - Core directive: *"The backend owns evidence truth; you own language synthesis. Adhere strictly to backend evidence directives."*
   - Negative constraints: *"Never extrapolate unrecorded facts. Never convert absence into a negative clinical claim (e.g., state 'records do not contain', NOT 'you do not have'). Never diagnose, triage, score severity, or advise medication adjustments."*
   - Provenance directive: *"Reference supporting records using only the provided [REC-N] tokens."*
2. **Sanitized Context Block**:
   - Serialized, tokenized health records for the patient.
3. **Backend Evidence Directives Block**:
   - `Status`: `SUFFICIENT` | `PARTIALLY_SUFFICIENT` | `INSUFFICIENT`
   - `Directives`: The authoritative backend assessment (e.g., *"blood_group is not recorded"* or *"clinic is unrecorded"*).
   - `Temporal Directive`: *"Temporal scope: current. Distinguish ongoing items from stopped/resolved records."*
4. **User Query**:
   - The user's natural language question.

### Output Shape Constraint vs. Factual Verification
> [!IMPORTANT]  
> Structured output mechanisms (e.g., OpenAI JSON Schema) constrain **syntactic output shape** to ensure Pydantic parseability. They do **NOT** provide semantic or factual truth guarantees. Authoritative validation remains entirely with the server.

* **Stage 1 (Syntactic Shape Constraint)**: OpenAI Structured Outputs enforces that the JSON response matches:
  ```python
  class LLMResponsePayload(BaseModel):
      answer_text: str
      cited_references: list[str]
  ```
* **Stage 2 (Server-Side Semantic & Citation Validation)**:
  - The adapter resolves `cited_references` to true UUIDs via the local reference map.
  - The API layer (`backend/app/api/health_inquiry.py`) validates that all resolved UUIDs exist in the authenticated patient's database records.
  - Any foreign, unmapped, or hallucinated citation is deterministically stripped by the server.

## 7. Failure Modes & Recovery Strategies

| Failure Mode | Root Cause | Detection Mechanism | Gateway Recovery Strategy | User Experience |
| :--- | :--- | :--- | :--- | :--- |
| **Network Timeout** | External provider latency exceeds timeout threshold | `asyncio.TimeoutError` or `httpx.TimeoutException` | Catch timeout; execute 1 rapid retry (shortened timeout). If retry fails, fall back to deterministic M1 synthesis using `evidence.evidence_directive`. | User receives factual, grounded answer derived from database evidence directive; no crash. |
| **HTTP 429 (Rate Limit)** | API quota or concurrency exceeded | HTTP 429 response code | Exponential backoff with jitter (max 2 retries). If still rate-limited, fall back to deterministic synthesis. | User receives grounded answer without interruption; warning logged for capacity planning. |
| **Provider Outage (5xx)** | Provider service degradation | HTTP 500, 502, 503 response | Immediate fallback to deterministic M1 synthesis without retrying. | High availability maintained; service seamlessly degrades to deterministic template. |
| **Malformed JSON Output** | Parsing error despite schema constraints | `json.JSONDecodeError` or Pydantic `ValidationError` | Strip potential markdown wrapping (` ```json `). If still unparseable, fall back to deterministic M1 synthesis. | Clean response delivered to user; unparseable payload logged for prompt analysis. |
| **Provider Safety Refusal** | Model safety filter flags query as medical advice | Empty completion choices or refusal response field | Intercept refusal; substitute standardized neutral advisory explaining provider filter activation while supplying the direct evidence directive. | *"The synthesis assistant was unable to format this response due to external safety filters. Your records show: [evidence_directive]."* |
| **Hallucinated Citations** | Model cites unprovided tokens or fake records | Token not present in server-side `reference_map` | Server-side citation filter drops invalid references deterministically. | User receives grounded text; invalid citation references are omitted from sources. |

## 8. Measurable Hypotheses: Cost, Token Budget, and Latency

> [!NOTE]  
> All cost, token, and latency metrics are treated as **measurable empirical hypotheses** to be validated during testing, not assumed architectural facts.

### 1. Token Budget Hypotheses
* **Hypothesis 1 (Input Tokens)**: System prompt (~350 tokens) + Sanitized Context (~300–800 tokens) + Evidence Directives (~50 tokens) + Query (~25 tokens) will result in a total prompt payload of **725 to 1,225 tokens** per typical inquiry.
* **Hypothesis 2 (Output Tokens)**: Synthesized answer + citation token array will consume **150 to 350 output tokens**.

### 2. Latency Hypotheses (Synchronous Execution)
* **Hypothesis 3 (Gateway Overhead)**: Sanitization, prompt construction, and token mapping will introduce **$\le$ 10ms** of local compute overhead.
* **Hypothesis 4 (External Inference)**: OpenAI `gpt-4o-mini` will return completions within **800ms to 1,600ms** under normal network conditions.
* **Hypothesis 5 (Total End-to-End Latency)**: The full request cycle will complete within **$\le$ 2.0 seconds** in $\ge 95\%$ of queries.

### 3. Cost Hypotheses
* **Hypothesis 6 (Unit Cost)**: At standard commercial API pricing (~$0.15/1M input tokens, ~$0.60/1M output tokens), individual inquiry synthesis will cost approximately **$0.0002 to $0.0004**.

Before enabling a live commercial LLM provider in a production environment:

2. **Training Prohibition Verification**: Confirm that provider terms explicitly prohibit using API inputs or outputs for foundation model training or improvement.
3. **Regulatory Compliance (HIPAA / BAA)**: If deploying in environments subject to HIPAA or GDPR, verify that an active Business Associate Agreement (BAA) or Data Processing Addendum (DPA) covers the inference endpoint.
4. **Transport Encryption**: Enforce TLS 1.3 encryption with strict certificate validation on all outbound provider connections.
5. **Secret Hygiene**: Provider API keys must be injected via secure runtime environment variables; keys must never be committed to source repositories or logged.

## 11. Evaluation Strategy: MockLLMProvider vs. Live Provider

To prevent regressions and verify synthesis quality, M2 introduces an automated comparative test harness:

```
                            [Evaluation Query Suite]
                                       │
                      ┌────────────────┴────────────────┐
                      ▼                                 ▼
           [MockLLMProvider Run]               [OpenAI Live Provider Run]
           (Deterministic Truth)               (Synthesized Language)
                      │                                 │
                      └────────────────┬────────────────┘
                                       │
                                       ▼
                     [Automated Comparative Invariant Checks]
                     1. EvidenceStatus parity (must match backend truth)
                     2. Cited entity parity (same clinical records cited)
                     3. Hallucination assertion check (no fabricated values)
                     4. Absence phrasing check (records do not contain...)
                     5. Temporal accuracy check (no active/stopped confusion)
```

### 7 Core Evaluation Categories
1. **Grounding & Entailment**: Assertions in the synthesized text are directly supported by context records.
2. **Hallucination Prevention**: When attributes are missing/null, the live model explicitly acknowledges the absence and never fabricates values.
3. **Citation Integrity**: Emitted citation tokens reconcile to genuine patient-owned records.
4. **Temporal Discrimination**: Stopped medications and resolved conditions are not described as active or current.
5. **Absence Phrasing**: Unrecorded entities produce "records do not contain" phrasing, never negative diagnostic claims ("you do not have").
6. **Safety Precedence**: Acute symptom queries produce no external network calls and return the fixed advisory.
7. **Tenant Isolation**: Queries executed under User B's token receive zero information or citations from User A's health records.

## 12. Safety Regression Requirements

> [!CAUTION]  
> Deterministic safety pattern matching (`evaluate_safety`) in `backend/app/health/safety_guardrails.py` is an inviolable system boundary.

1. **Defense-in-Depth Pre-Flight**: Acute symptom patterns are scanned before any context assembly or gateway dispatch.
2. **No External LLM Network Call**: When `safety_state.triggered == True`, the gateway intercepts the request immediately. Zero tokens are sent to OpenAI, eliminating latency and privacy exposure for acute emergencies.
3. **No LLM Overrides**: The LLM is never consulted to evaluate symptom severity, triage urgency, or rephrase the safety advisory.
4. **Mandatory CI Regression Gate**: The test suite must assert that all acute symptom queries produce the exact, unaltered `SAFETY_ADVISORY` text with zero external network activity.

## 16. Risks and Unresolved Decisions

### Architectural Risks
1. **Overzealous Provider Safety Refusal**:
   - *Risk*: OpenAI's content moderation may occasionally flag benign questions mentioning prescription drugs or physical symptoms.
   - *Mitigation*: Emphasize in the prompt that the system is summarizing personal health history rather than dispensing advice; implement automated fallback to the evidence directive if a refusal occurs.
2. **Reference Token Hallucination**:
   - *Risk*: Model may output `[REC-9]` when only `[REC-1]` and `[REC-2]` were provided.
   - *Mitigation*: The server-side reconciliation dictionary silently drops unmapped tokens, preventing invalid citations from reaching the client.

### Unresolved Decisions for Implementation
1. **Prompt Sanitization Level for Health Profiles**:
   - *Decision*: Format date of birth as age in years (`Age: 41`) and biological sex, omitting the exact birth date from the prompt to maximize privacy.
2. **Default Provider Fallback in Development**:
